# Community design references for Aureform

The original Aureform code and distributed design work use [Apache 2.0](../LICENSE). This document records external research leads and their independent licenses; linking a Community file does not include it in that grant or mean its assets are bundled. See [third-party notices](../THIRD_PARTY_NOTICES.md).

Checked on 2026-10-18. This is a comparison of public design resources and their reuse terms, with proposed visual and interaction patterns for Aureform's Next.js, Base UI and shadcn components. Research changed only this document. No product source, Figma file, subscription or public archive was changed.

Use **Obra Community** as the first candidate for attributed component reuse. Study **Nuxt UI** for a complete web application system and **Forms & Tables** for enterprise table composition. Use **Untitled UI's dedicated table file** as a visual reference; its publisher's redistribution restrictions prevent treating the free download as an unrestricted asset donor.

The earlier [Aureform 1.1 consumer checkpoint](consumer-verification-1.1.md) records successful installation, frozen-lock replay, TypeScript, ESLint and production builds for three isolated consumers. Its official shadcn consumer reproduced the MagneticButton composition defect. Those results apply to the source inputs captured in that report. The current 83-entry registry refresh passed all 85 production UI/provider checks in [the actual current-source report](../artifacts/consumer-registry-provider-refresh-1.1-report.json), also recorded in [verification results](verification-results.json). Final ZIP QA remains pending; the detailed artifact is excluded from the source ZIP, and this research document does not certify new archives.

Paid files have separate restrictions. This establishes a platform baseline, not proof that an external download, paid kit or every item shown in a preview has the same grant.

## Primary supplements and corrected leads

**UI Prep — Figma Freebie, Data Tables 7.0, by Molly Hellmuth:** [current author download](https://uiprep.gumroad.com/l/LdhHZR), linked from the [author's table guide](https://www.uiprep.com/blog/the-ultimate-guide-to-designing-data-tables). The public product description confirms a native `.fig` file, a quick-start guide and six playground exercises covering instances, variants, component updates, clipping and Auto Layout. It is a genuine table kit, with Material/Bootstrap ancestry; study its table structure and density rather than using those skins as Aureform's visual target.

The Community listing lead is [UI Prep Data Tables](https://www.figma.com/community/file/888102678933348280), found through an indexed directory. **A primary-author link to that listing and its equivalence to current 7.0 were not established.** The verified current distribution is Gumroad; no checkout/download transaction was performed. [UI Prep's published license](https://www.uiprep.com/license) governs its purchased design system and forbids redistribution as stock, tools, templates or source files, including modified versions. Its applicability to this freebie is not stated clearly enough to claim kit-redistribution rights. Keep it a reference until a freebie-specific grant is available.

For inputs, Molly's [maintainable-inputs guide](https://www.uiprep.com/blog/5-tips-to-design-maintainable-inputs-in-figma) confirms a free native input kit built with variants, nested base components, label/feedback atoms and Auto Layout. It is useful evidence for form architecture; no separate verified Community URL or redistribution grant is claimed here.

**Shadcn Studio exists, but its current public Figma link is a Design preview, not a verified Community free kit:** [publisher's Figma page](https://shadcnstudio.com/figma) links [the actual Nova Pro preview](https://www.figma.com/design/N1Be7W5xCHcpdgjcjyoZs3/shadcn-studio-figma-uikit-pro-nova-preview). Publisher describes native variants, slots, themes and dashboard/app layouts; edit access to that preview was not tested. Its [January 13, 2026 terms](https://shadcnstudio.com/license) add redistribution/competition restrictions to the advertised free MIT license and explicitly exclude redistributed UI libraries, derivative Figma kits and starter kits under paid licenses. Use public previews to compare information hierarchy; do not copy Studio assets into Aureform.

**Base UI is the behavior foundation:** its [primary site](https://base-ui.com/) confirms unstyled React primitives and MIT commercial use. That is not a Figma asset license or a visual design system. Keep Base UI's composition and accessibility behavior while applying independently designed visual treatments.

The owner reports eight subscribed libraries and real Material 3/Simple SDS Button assets. The generic DataTable search returned many icons. Those findings do not establish native editable table cells, rows or complete table workflows. The dedicated resources above address that gap.

## Concrete adoption priorities

These are design proposals based on the references, not claims that every state or block is present in each free file. Preserve the current component APIs and appearance configuration; apply patterns to existing families.

| Area                                     | Recommended reference                                                                              | What to design for Aureform                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Buttons: variants, shapes and states** | Obra's inspected component preview; Nuxt Button; Shadcn Space Button                               | A shared matrix for filled, outline, soft/secondary and ghost emphasis; rounded rectangle, pill and circular icon actions; leading/trailing icons; default, hover, pressed, keyboard focus, disabled, loading and success feedback. Keep label placement stable during loading. Use gradients/glass selectively for featured actions and keep small table actions visually quiet.                                                                |
| **Actual data tables**                   | Forms & Tables components; Untitled table anatomy; UI Prep's table guide                           | A table card with title/count, search, filter chips and a column chooser; primary cells with secondary metadata; aligned numeric columns; distinct hover/selected/focus states; selection with a contextual bulk-action bar; sortable headers and clear pagination. Provide compact and comfortable density, plus loading, empty, filtered-empty and error states. Recreate visual assets independently where reuse is restricted or unresolved. |
| **Forms and controls**                   | Obra; Nuxt AuthForm; UI Prep inputs guide                                                          | Label, field, helper and error as one layout; optional/required metadata; checkbox/radio/select/combobox consistency; password visibility and readable validation. Give invalid and focus states distinct treatments. Let helper/error text grow without colliding with the next field; use explicit feedback beyond color alone.                                                                                                                |
| **Sidebars, tabs and dialogs**           | Forms & Tables navigation/modal walkthroughs; Nuxt's application system; Shadcn Space              | Expanded/collapsed sidebar with workspace switcher, nested groups, active item, counts and footer actions; consistent top-level and in-panel tabs; concise dialog header, content and action area. Retain Base UI keyboard/focus behavior. Make row actions available on keyboard focus as well as hover.                                                                                                                                        |
| **Dashboard cards and charts**           | Nuxt system; Forms & Tables cards/charts; Shadcn Space product previews                            | Cohesive metric cards with period and comparison, chart cards with title/legend/controls, and activity/table cards using one spacing system. Use Aureform material/tint treatments around a legible plot area. Apply these shells to the owner's existing six chart kinds and seven additional kinds as those implementations stabilize.                                                                                                         |
| **Auth and application blocks**          | Nuxt AuthForm; Forms & Tables sign-in-modal walkthrough; shadcncraft's limited free sample layouts | A focused auth card with provider buttons, divider, email/password, validation and submit progress; a wider onboarding layout with supporting content; a dashboard shell combining sidebar, page header, tabs, metric cards and a real data table. Treat full Pro layouts as references, not free supplied assets.                                                                                                                               |

The intended direction is a coherent premium web system: balanced type hierarchy, subtle tint, controlled radius, restrained elevation and selective motion. Table/form surfaces should retain strong text contrast in both Light and Dark. Derive dark treatments from Aureform's own appearance tokens; Obra Community's included style is light-only.

Native reusable-component evidence should mean a real component/component set with properties, editable nested text, token references and resizing behavior. A cover, screenshot, Pro-only image or Lucide Table glyph cannot substitute for that evidence.
