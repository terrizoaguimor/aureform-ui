## Descubrimiento del registro: soporte actual

El [catálogo publicado](https://aureformui.com/r/registry.json) devolvió 107 entradas y ningún `content` en sus registros de archivos. El [payload de Button](https://aureformui.com/r/button.json) sí incluye código instalable y dependencias Base UI. Son archivos con funciones distintas. La revisión inicial comprobó HTTP y estructura JSON. Un [suplemento técnico del 20 de octubre](promotion/registry-readiness.md) ejecutó después el validador original upstream con una sola entrada e instaló Button y el proveedor de apariencia en un consumidor Next.js nuevo. Pasaron TypeScript, compilación de producción y una prueba de interacción acotada; el fixture registró una advertencia por favicon ausente. La evidencia cubre dos elementos y una configuración, no todos los componentes ni la aceptación oficial.

La vía oficial propone un namespace como **`@aureform`** y URL `https://aureformui.com/r/{name}.json`. No estaba ocupado en el directorio consultado; tampoco está reservado ni publicado. El [borrador](promotion/github-submissions.md#official-shadcn-registry-directory) incluye el SVG original obligatorio. La prueba de consumidor configuró ese namespace manualmente. Antes de una contribución externa autorizada hay que revisar de nuevo su disponibilidad y el procedimiento vigente, ejecutar las comprobaciones completas que exija upstream y adjuntar los [resultados registrados](promotion/registry-readiness.md). La prueba local no ejecutó el wrapper raíz **`pnpm validate:registries`** ni validó las otras 479 entradas. [Procedimiento](https://ui.shadcn.com/docs/registry/registry-index), [validador real](https://github.com/shadcn-ui/ui/blob/main/apps/v4/scripts/validate-registries.mts).

La documentación actual de shadcn admite registros públicos por dirección GitHub sin entrar en el directorio de namespaces. Aureform contiene `registry.json` en la raíz, pero aquí no se probó ese transporte con un consumidor actual. Mantener el comando con URL completa hasta superar esa prueba separada. [Distinción oficial](https://ui.shadcn.com/docs/registry/registry-index), [guía de registros GitHub](https://ui.shadcn.com/docs/registry/github).

## Flujo para propuestas externas

Los borradores son material de revisión, **no autorización de publicación**. Cualquier PR, issue, discusión, mensaje o formulario externo requiere autorización explícita del usuario para ese destino y contenido. El formulario de awesome-shadcn crea un PR y también cuenta como escritura externa. La autorización no elimina reglas editoriales o de contribución exclusivamente humana.

Antes de cada envío autorizado, releer guía/plantilla, buscar entradas y PR pendientes, reproducir el ejemplo de la versión propuesta, declarar la relación del mantenedor y hacer un cambio enfocado en el archivo indicado. Confirmar únicamente las comprobaciones realmente realizadas. El PR de la tabla de diseño debe incluir la advertencia de Figma congelado; el directorio de registros, los resultados actuales de consumidor/validador.

Atender ajustes en el mismo PR y respetar rechazos. Repetir la revisión manual cuando cambie la versión, se cumpla un requisito de madurez o se prepare otro envío. Sin bot stars, saturación de palabras clave, promoción pagada, issues promocionales repetidos, supuestos respaldos de GitHub o ubicación garantizada. No se configura seguimiento periódico.
