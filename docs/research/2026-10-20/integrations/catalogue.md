## TanStack Query

**P0 · Primary option · Small effort.**

Client cache and query/mutation lifecycle over the consumer’s existing API; distinct from TanStack Table.

**Aureform today:** DataTable already supports controlled queries and external filtering, sorting and pagination; application records use local demo state.

**Proposed interface:**

- Complete an optional recipe that maps DataTable query/onQueryChange and external mode to an authenticated fetcher.
- Preserve loading, empty, error, retry, cancellation and workspace-switch behavior.

**Runtime:** Browser client; privileged operations require the consumer backend when applicable. Documented compatibility only; no external integration was runtime-tested in Aureform.

**SDK licensing:** MIT. **Service boundary:** Depends on the selected provider, component and deployment; review the linked platform/service terms.

**Limits and implementation considerations:** Already supplied table controls need a provider recipe, not another public table API. Scope query keys by identity/workspace; caching does not authorize records.
